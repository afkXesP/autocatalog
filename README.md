# AutoCatalog

Проект состоит из трёх частей:

1. Выгрузка товаров из Ozon Seller API в CSV.
2. Формирование и отправка утренней сводки в Telegram.
3. Очистка исходного каталога `catalog_raw.csv`.

## Структура проекта

```
project/
├── input/
│   └── catalog_raw.csv
├── output/
│   ├── products.csv
│   └── catalog_clean.csv
├── src/
│   ├── ozon_export.py
│   ├── telegram_report.py
│   └── clean_catalog.py
├── .env
├── .env_example
├── requirements.txt
└── README.md
```

## Требования

- Python 3.11+
- Доступ к Ozon Seller API
- Telegram-бот (создаётся через `@BotFather`)
- Зависимости из `requirements.txt`: `requests`, `python-dotenv`

## Установка

```bash

cd autocatalog

python -m venv .venv
```

## Переменные окружения

Создать `.env` в корне проекта (пример - в `.env_example`):

```env
# Ozon Seller API
OZON_CLIENT_ID=your_client_id
OZON_API_KEY=your_api_key

# Telegram

TELEGRAM_CHAT_ID=your_chat_id

# Порог минимального остатка
LOW_STOCK_THRESHOLD=5
```

Секретные значения не хранятся в коде и не должны попадать в Git.

## Задача 1. Выгрузка товаров из Ozon Seller API

**Скрипт:** `src/ozon_export.py`
**Запуск:** `python src/ozon_export.py`
**Результат:** `output/products.csv`

### Используемые методы API

| Метод | Назначение |
|---|---|
| `POST /v3/product/list` | список товаров продавца (с пагинацией) |
| `POST /v3/product/info/list` | подробная информация по товарам |

Запросы выполняются с заголовками `Client-Id`, `Api-Key`, `Content-Type: application/json`.

### Пагинация

Запрос списка товаров:
```json
{
  "filter": { "visibility": "ALL" },
  "limit": 100,
  "last_id": ""
}
```
После каждой страницы курсор `last_id` из ответа передаётся в следующий запрос. Пагинация останавливается, если API вернул пустой список или в ответе нет `last_id`.

### Получение деталей

`product_id`, собранные из списка товаров, запрашиваются в `/v3/product/info/list` батчами. Размер батча задаётся `OZON_BATCH_SIZE` (по умолчанию 100) - это снижает число HTTP-запросов.

### Обработка ошибок и повторные попытки

Повтор запроса выполняется при HTTP `429, 500, 502, 503, 504` и при сетевых ошибках (`RequestException`). Если сервер прислал заголовок `Retry-After`, используется его значение; иначе - экспоненциальная задержка `2^attempt` секунд (1, 2, 4 сек при 3 повторных попытках, `OZON`-константа `MAX_RETRIES=3`). После исчерпания попыток ошибка пробрасывается вызывающему коду.

### Цена и остатки

- Цена может приходить строкой или вложенным объектом `{"price": ...}` - оба варианта поддержаны; если цены нет, поле в CSV пустое.
- Остаток - сумма `present` по всем складам из `stocks.stocks`; если данных нет, `0`.

### Формат результата (`output/products.csv`)

| Поле | Описание |
|---|---|
| `export_date` | дата выгрузки |
| `offer_id` | артикул товара |
| `name` | название товара |
| `price` | цена товара |
| `stock` | остаток товара |

```csv
export_date,offer_id,name,price,stock
2026-09-09,232141,Полотенце,1000.00,0
```

### Логирование

Начало выгрузки, номер и размер каждой страницы, общее число полученных товаров, завершение пагинации, прогресс по батчам деталей, HTTP-ошибки и повторные попытки, путь к сохранённому CSV и число строк.

## Задача 2. Утренняя сводка в Telegram

**Скрипт:** `src/telegram_report.py`
**Запуск:** `python src/telegram_report.py`

Читает `output/products.csv` и отправляет сводку в Telegram-чат через бота.

### Формат сообщения

Для каждого товара: название, цена, остаток. Если `stock < LOW_STOCK_THRESHOLD`, добавляется пометка «заканчивается».

```
Утренняя сводка по товарам

Полотенце
Цена: 1000.00 ₽
Остаток: 0 шт. - заканчивается
```

| Остаток | Порог = 5 | Статус |
|---|---|---|
| 0, 1, 4 | < 5 | заканчивается |
| 5, 10 | ≥ 5 | обычный |

### Получение `TELEGRAM_CHAT_ID`

1. Создать бота через `@BotFather`, получить токен.
2. Написать боту любое сообщение.
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
4. Взять `chat.id` из ответа и указать в `.env`.

### Разбиение длинных сообщений

Сообщение делится на части не длиннее 3500 символов (константа в коде), преимущественно по границам строк товара; если отдельная строка сама длиннее лимита - она режется принудительно.

## Задача 3. Очистка каталога

**Скрипт:** `src/clean_catalog.py`
**Запуск:** `python src/clean_catalog.py`
Вход: `input/catalog_raw.csv` → выход: `output/catalog_clean.csv`.

### Входной / выходной форматы

Вход: `offer_id, name, price, stock`
Выход: `offer_id, brand, oem, name, quantity, price, stock`

### Правила обработки

**`offer_id`** - пробелы убираются, регистр приводится к верхнему (`mv 1028f` → `MV1028F`).

**Бренд** - извлекается по словарю (в исходнике нет отдельного поля):
```python
BRAND_MAP = {
    "mavico": "Mavico",
    "dba": "DBA",
    "деталиус": "Деталиус",
}
```
Поиск без учёта регистра; если не найден - поле пустое.

**OEM** - приоритет: (1) число после слова `OEM` → (2) артикул, найденный в названии по шаблону → (3) `offer_id`. Дефисы и пробелы убираются (`OEM 2101-3502090` → `21013502090`).

**Количество** - `N шт` / `комплект N шт` / `набор N шт` → `N`; `пара` → `2`; если не указано → `1`.

**Название** - из строки убираются бренд, основной артикул, слова про количество, лишние пробелы и пунктуация по краям/перед знаками препинания.

**Цена** - приводится к числу с двумя знаками после запятой. Поддерживаются: `1 500 руб`, `1500.00`, `1500р`, `1 500 rub`, `8 990,00`, `3 200 р`, `890 руб.`, `от 450 руб` (трактуется как `450.00` - в исходнике нет отдельного поля для диапазона/минимальной цены). Если цену не удалось распознать - строка пропускается.

**Остаток** - приводится к целому числу; отсутствующий или некорректный → `0` (не является причиной удаления строки).

**Пустые строки** - пропускаются, если нет `offer_id`, названия или корректной цены.

**Дубликаты** - по нормализованному `offer_id`; сохраняется первая корректная запись.

**Кодировка** - `utf-8-sig` для чтения и записи (поддержка кириллицы, корректное открытие в Excel).

## Работа с документацией и ИИ

Использовались официальная документация Ozon Seller API (docs.ozon.ru, dev.ozon.ru), документация Telegram Bot API, и инструменты ИИ - для анализа структуры ответов API, обработки ошибок и проверки крайних случаев.

В модель передавались: описание задачи, названия используемых методов API, примеры запросов/ответов (без секретных значений), сообщения об ошибках, структура исходного CSV, отдельные фрагменты кода для проверки типизации и обработки данных.

Примеры формулировок запросов:
- «Проверь структуру ответа метода Ozon Seller API и предложи извлечение цены и остатков»
- «Как реализовать пагинацию через `last_id` с обработкой пустой страницы?»
- «Проверь обработку HTTP 429 и повторные попытки запроса»
- «Предложи правила очистки цены, OEM, бренда и количества в исходном CSV»
- «Проверь крайние случаи при разбиении длинного сообщения Telegram»

### Проверка актуальности методов

Методы API не выдумывались по названиям - использовались реальные методы из документации, а структура ответа дополнительно проверялась тестовыми запросами к API:
- `product/list` вернул `product_id`, `offer_id`, `sku`, `last_id`;
- `product/info/list` вернул название, цену, артикул, данные об остатках;
- пагинация проверена отдельным запросом с полученным курсором.

## Крайние случаи и допущения (задача 3)

Замеченные случаи: пустые строки без `offer_id`/названия/цены; дубли `offer_id`; цена с пробелами, валютными обозначениями и запятой как десятичным разделителем; формат «от N руб»; отсутствующий остаток; количество в форматах «шт», «комплект», «набор», «пара»; отсутствие отдельных полей бренда и OEM; артикулы с дефисами/пробелами; лишние пробелы и пунктуация в названиях.

Принятые допущения:
- нет количества → `1`; «пара» → `2`;
- нет остатка → `0`;
- «от N руб» → цена `N`;
- нет OEM → используется `offer_id`;
- бренд не найден в словаре → поле пустое;
- при дублировании `offer_id` - сохраняется первая корректная запись.
