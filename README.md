# Тестовое задание МАВИКО

Тестовое задание на позицию Python-разработчика по автоматизации.

Проект состоит из трёх частей:

1. Выгрузка товаров из Ozon Seller API в CSV.
2. Формирование и отправка утренней сводки в Telegram.
3. Очистка исходного каталога `catalog_raw.csv`.

## Структура проекта

```text

├── input/
│   └── catalog_raw.csv
├── output/

│   └── catalog_clean.csv

│   ├── telegram_report.py

├── .env
````

# Задача 1. Выгрузка товаров из Ozon Seller API

Скрипт:

```
src/ozon_export.py
```

Скрипт получает список товаров продавца из Ozon Seller API, запрашивает подробную информацию по товарам и сохраняет результат в CSV.

## Запуск

Bash

```
python src/ozon_export.py
```

Результат сохраняется в файл:

```
output/products.csv
```

## Используемые методы API

Для получения списка товаров используется метод:

```
POST /v3/product/list
```

Для получения подробной информации о товарах используется метод:

```
POST /v3/product/info/list
```

Запросы выполняются с использованием заголовков:

```
Client-Id
Api-Key
Content-Type: application/json
```

## Пагинация

Получение списка товаров выполняется с учётом пагинации.

В запросе передаются:

JSON

```
{
  "filter": {
    "visibility": "ALL"
  },
  "limit": 100,
  "last_id": ""
}
```

После получения страницы скрипт извлекает значение `last_id` и использует его для следующего запроса.

Пагинация завершается, если:

* API вернул пустой список товаров;

* в ответе отсутствует следующий курсор `last_id`.

## Получение деталей товаров

После получения списка товаров из ответа извлекаются `product_id`.

Подробная информация запрашивается батчами. Размер батча задаётся переменной:

env

```
OZON_BATCH_SIZE=100
```

Это позволяет получать информацию сразу по нескольким товарам и уменьшает количество HTTP-запросов.

## Обработка ошибок и повторные попытки

Для временных ошибок реализованы повторные попытки.

Повторяются запросы при следующих HTTP-статусах:

```
429
500
502
503
504
```

Также повторная попытка выполняется при сетевых ошибках.

Если API возвращает заголовок `Retry-After`, скрипт использует его значение для определения задержки перед повторным запросом.

Если заголовок отсутствует, используется экспоненциальная задержка:

```
1 секунда
2 секунды
4 секунды
8 секунд
```

После исчерпания количества попыток ошибка передаётся вызывающему коду.

## Логирование

Во время выполнения записываются:

* начало выгрузки;

* номер полученной страницы;

* количество товаров на странице;

* общее количество полученных товаров;

* завершение пагинации;

* получение деталей батчами;

* ошибки HTTP-запросов;

* повторные попытки;

* путь к сохранённому CSV;

* количество сохранённых строк.

## Обработка цены

В зависимости от структуры ответа API цена может быть представлена строкой либо вложенным объектом.

Скрипт поддерживает оба варианта и преобразует значение в строковое представление.

Если цена отсутствует, в CSV записывается пустое значение.

## Обработка остатков

Остаток рассчитывается как сумма значений `present` по всем складам, которые возвращает API.

Если информация об остатках отсутствует, используется значение `0`.

## Получение Telegram `chat_id`

1. Создать бота через `@BotFather`.

2. Получить токен бота.

3. Отправить боту любое сообщение.

4. Открыть в браузере следующий адрес:

   [https://api.telegram.org/bot](https://api.telegram.org/bot)<ТОКЕН>/getUpdates

5. В ответе найти значение `chat.id`.

6. Указать его в `.env`:

env

```
TELEGRAM_CHAT_ID=your_chat_id
```

## Ограничение длины сообщения

Telegram ограничивает размер одного текстового сообщения.

Поэтому перед отправкой сводка разбивается на части длиной не более 3500 символов.

Разбиение выполняется преимущественно по строкам, чтобы не разделять информацию о товаре посередине.

Если отдельная строка превышает допустимую длину, она разбивается принудительно.

## Формат входного файла

Исходный файл должен содержать следующие столбцы:

```

name
price

```

## Формат выходного файла

Очищенный файл содержит:

```
offer_id
brand
oem
name
quantity
price
stock
```

## Правила обработки

### Нормализация `offer_id`

Для значения `offer_id`:

* удаляются пробелы;

* значение переводится в верхний регистр.

Пример:

```
mv 1028f
```

преобразуется в:

```
MV1028F
```

### Извлечение бренда

Бренд извлекается из названия по словарю:

Python

Запустить

```
BRAND_MAP = {
    "mavico": "Mavico",
    "dba": "DBA",
    "деталиус": "Деталиус",
}
```

Поиск выполняется без учёта регистра.

Если бренд не найден, поле `brand` остаётся пустым.

Словарь используется потому, что в исходном CSV отсутствует отдельный столбец с брендом.

### Извлечение OEM

Для определения OEM используется следующий приоритет:

1. Явно указанный номер после слова `OEM`.

2. Артикул, найденный в названии по шаблону.

3. `offer_id`, если отдельный OEM не найден.

Например:

```
OEM 2101-3502090
```

преобразуется в:

```
21013502090
```

Дефисы и пробелы в OEM удаляются.

Поскольку в исходном файле нет отдельного поля OEM, в некоторых случаях значение определяется как наиболее подходящий артикул из названия.

### Извлечение количества

Поддерживаются следующие варианты:

```
4 шт
комплект 4 шт
набор 4 шт
2 шт
пара
```

Правила обработки:

* `4 шт` → `4`;

* `комплект 4 шт` → `4`;

* `набор 4 шт` → `4`;

* `пара` → `2`;

* если количество не указано → `1`.

### Очистка названия

Из названия удаляются:

* бренд;

* основной артикул;

* обозначения количества;

* лишние пробелы;

* пробелы перед знаками препинания;

* лишняя пунктуация в начале и конце строки.

### Нормализация цены

Цена преобразуется в число и сохраняется с двумя знаками после запятой.

Поддерживаются варианты:

```
1 500 руб
1500.00
1500р
1 500 rub
8 990,00
3 200 р
890 руб.
```

Примеры:

```
1 500 руб → 1500.00
8 990,00 → 8990.00
250р → 250.00
3 200 р → 3200.00
```

Значения вида:

```
от 450 руб
```

трактуются как цена `450.00`.

Это допущение связано с тем, что в исходном CSV отсутствует отдельное поле для минимальной цены или диапазона цен.

Если цена отсутствует либо не может быть преобразована в число, строка пропускается.

### Нормализация остатка

Остаток преобразуется в целое число.

Если значение отсутствует или некорректно, используется значение `0`.

### Удаление пустых строк

Строка пропускается, если отсутствует:

* `offer_id`;

* название;

* корректная цена.

Отсутствующий остаток не является причиной удаления строки и заменяется на `0`.

### Удаление дубликатов

Дубликатом считается строка с уже встречавшимся нормализованным `offer_id`.

Сохраняется первая корректная запись, остальные записи с таким же `offer_id` пропускаются.

Она поддерживает кириллицу и позволяет корректно открывать CSV-файлы в Microsoft Excel.

Перед реализацией API-методы проверялись по документации Ozon Seller API.

Дополнительно структура фактического ответа проверялась тестовыми запросами к API:

# Крайние случаи и неоднозначности

В задаче 3 были замечены следующие случаи:

1. Пустые строки без `offer_id`, названия или цены.

2. Дубликаты с одинаковым `offer_id`.

3. Цена с пробелами, валютными обозначениями и запятой в качестве десятичного разделителя.

4. Цена в формате `от 450 руб`.

5. Отсутствующий остаток.

6. Количество в формате `шт`, `комплект`, `набор` или `пара`.

7. Отсутствие отдельного поля для бренда.

8. Отсутствие отдельного поля для OEM.

9. OEM, указанный после слова `OEM`.

10. Артикулы с дефисами и пробелами.

11. Лишние пробелы и знаки препинания в названиях.

Принятые допущения:

* если количество не указано, используется `1`;

* слово `пара` трактуется как `2`;

* если остаток отсутствует, используется `0`;

* значение `от N руб` трактуется как цена `N`;

* если OEM не найден, используется `offer_id`;

* если бренд не найден в словаре, поле `brand` остаётся пустым;

* при дублировании `offer_id` сохраняется первая корректная запись.
